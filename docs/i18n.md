# Internationalization (i18n)

This project uses [next-intl](https://next-intl.dev) for internationalization with locale-prefixed URLs (`/en/contacts`, `/es/contacts`).

## Supported locales

| Code | Language |
|------|----------|
| `en` | English (default) |
| `es` | Spanish |

## How it works

### URL structure

All pages are nested under `src/app/[locale]/`. When a user visits `/`, the proxy detects their preferred locale and redirects to `/{locale}/`. The default locale is `en`.

### Key files

| File | Purpose |
|------|---------|
| `messages/en.json` | English translation strings |
| `messages/es.json` | Spanish translation strings |
| `src/i18n/routing.ts` | Defines supported locales and default locale |
| `src/i18n/request.ts` | Loads the correct message file per request |
| `src/i18n/navigation.ts` | Locale-aware `Link`, `useRouter`, `usePathname`, `redirect` |
| `src/proxy.ts` | Locale detection (via `next-intl/middleware`) + auth checks |
| `src/app/[locale]/layout.tsx` | Wraps pages with `NextIntlClientProvider` |
| `next.config.ts` | `createNextIntlPlugin` wraps the Next.js config |

### Translation usage

**Server components** — use `getTranslations` from `next-intl/server`:

```tsx
import { getTranslations } from 'next-intl/server';

const Page = async () => {
  const t = await getTranslations('contacts');
  return <h1>{t('title')}</h1>;
};
```

**Client components** — use `useTranslations` from `next-intl`:

```tsx
'use client';
import { useTranslations } from 'next-intl';

const MyComponent = () => {
  const t = useTranslations('contacts');
  return <p>{t('addContact')}</p>;
};
```

**Interpolation** — pass variables in the second argument:

```tsx
t('editDescription', { name: contact.name })
// messages/en.json: "editDescription": "Update the details for {name}."
```

### Navigation

Use the locale-aware `Link` and `useRouter` from `@/i18n/navigation` instead of `next/link` and `next/navigation`. These automatically prefix the current locale to paths.

```tsx
import { Link, useRouter } from '@/i18n/navigation';

// Renders as /en/contacts or /es/contacts depending on locale
<Link href="/contacts">Contacts</Link>

// Router also handles locale prefixing
const router = useRouter();
router.push('/contacts');
```

### Server actions

Server actions use `getLocale()` from `next-intl/server` to prefix redirects, and `revalidatePath` for each supported locale:

```tsx
import { getLocale } from 'next-intl/server';
import { redirect } from 'next/navigation';

const locale = await getLocale();
redirect(`/${locale}/contacts`);
```

### Language toggle

The `LanguageToggle` component in the header uses `useRouter().replace()` to switch locales without a full page reload. It navigates to the same path under the new locale prefix.

## Adding a new locale

1. **Add message file** — copy `messages/en.json` to `messages/{code}.json` and translate the values.

2. **Register the locale** — add the locale code to the `locales` array in `src/i18n/routing.ts`:

   ```ts
   export const routing = defineRouting({
     locales: ['en', 'es', 'fr'],  // add 'fr'
     defaultLocale: 'en',
   });
   ```

3. **Update the language toggle** — add the locale label in `src/components/layout/language-toggle.tsx`:

   ```ts
   const localeLabels: Record<Locale, string> = {
     en: 'English',
     es: 'Español',
     fr: 'Français',  // add entry
   };
   ```

4. **Update the language message file** — add the label in each `messages/{code}.json` under the `language` key:

   ```json
   "language": {
     "label": "Language",
     "en": "English",
     "es": "Español",
     "fr": "Français"
   }
   ```

That's it. The proxy, routing, and `NextIntlClientProvider` handle the rest automatically.

## Adding a new translation string

1. **Add the key** to `messages/en.json` under the appropriate namespace:

   ```json
   {
     "contacts": {
       "newKey": "New value"
     }
   }
   ```

2. **Add the same key** to every other locale file (`messages/es.json`, etc.) with the translated value.

3. **Use the key** in your component:

   ```tsx
   // Server component
   const t = await getTranslations('contacts');
   t('newKey');

   // Client component
   const t = useTranslations('contacts');
   t('newKey');
   ```

### Namespaces

Translation keys are organized by namespace (the top-level key in the JSON). Current namespaces:

| Namespace | Used for |
|-----------|----------|
| `common` | Shared UI labels (sign in, cancel, delete, etc.) |
| `home` | Landing page content |
| `login` | Login page and form |
| `contacts` | Contact list, add, edit, delete pages |
| `contactForm` | Contact form field labels |
| `errors` | Error messages and error pages |
| `notFound` | 404 page |
| `language` | Language selector labels |
